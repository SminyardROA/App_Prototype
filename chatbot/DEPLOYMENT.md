# Chat privacy and launch checklist

## Render build and update

Keep the repository root as Render's Root Directory. Use `npm ci --prefix chatbot`
as the Build Command and `node chatbot/server.js` as the Start Command. This
retains the root-level widget assets and uses the standalone chatbot's lockfile.
External deployment lockfiles must use public registry URLs, not Replit's
internal package mirror. The widget uses the origin of its own script URL, so
Render installations call Render while Replit previews call their preview server.

Render is the intended chatbot deployment target, not the separately published
Replit API scaffold. Publishing on Replit does not configure or migrate a Render
database. Existing public-site approval blocks remain in place.

The protected course-builder route is documented in [SOURCE_PACK_API.md](./SOURCE_PACK_API.md).

**ROA's standard:** ROA must not retain chat text, names, emails, IP addresses, or session IDs in its database, files, hosting logs, or analytics. A short-lived IP address in process memory is permitted solely for fair rate limiting; it expires with the limiter window and is not persisted. Anonymous topic counts are allowed. Outside providers may retain data under their own policies. Keep Anthropic, Voyage AI and Pinecone. The widget remains blocked on roa.org and www.roa.org pending ROA approval; the server rejects those public-site Origins/Hosts. This is a development chat, not an approved public deployment.


## Notice and release

Current development notices in `widget.js` and `testpage.html` describe only what application code can establish and state that hosting logs remain unverified. After completing the ROA-controlled storage checklist, proposed short public notice:

> ROA does not save chats. Your questions are processed by AI service providers to generate answers. Please do not enter personal information.

Do not publish that sentence as an ROA-wide fact until hosting, analytics and legacy stores have been checked. Then update the published privacy policy to name the actual processors and link their policies. Only ROA approval should trigger removing the existing public-site code blocks and installing the widget on roa.org.

## Web search

**Web search is already off.** The live `Anthropic.messages.stream` call supplies no web-search tool, and retrieval searches the Pinecone knowledge index rather than the open web. Keep web search off by leaving tools unconfigured; do not add Anthropic web-search tooling or another search API without an explicit ROA choice and a new review. Turning off Pinecone would turn off document retrieval, not web search.


## ROA-controlled storage checklist (not yet approved)

- The application no longer writes chat transcripts or signup details; `/save-email` is absent (404), even if `DATABASE_URL` is set. Remove unused `DATABASE_URL`, `SHEETS_WEBHOOK_URL`, `EMAIL_DESTINATION` and `EMAIL_BACKUP_FILE` from the Render service. Optional invitations link to separate signup sites, outside this chat. The fair rate limiter holds IP keys **only in memory** for its window (15 minutes for chat); expired entries are removed on subsequent requests, and process restart discards all entries. No IP is written by application code to a database, file or log. No per-user session identifier is generated by the chat backend.
- Do **not** silently delete legacy signup rows, old files or backups. ROA must inventory and authorize removal of previously collected records in old databases, files, logs and backups. This repository cannot prove those external stores are empty.
- **Verify yourself on the actual Render/hosting configuration before saying “ROA doesn't save chats”:** turn off or redact request-body, query-string, IP and cookie logging at reverse proxies, load balancers, app and error log drains; inspect real access/error logs, analytics, crash reports, traces, database/backups, CDN and retention settings. Disable IP/session collection by analytics on the chat path. Application logs must not include prompts, replies, raw provider errors, headers or IPs. Browser chat state is cleared on close; the invitation counter in browser session storage contains only answer count/shown state, not an identifier.
- If anonymous topic counts are added later, emit only predetermined broad categories and counts without question text, IP, timestamped per-user events or session keys. No event analytics are configured by this backend today.
